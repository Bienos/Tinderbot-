## Supporting interpersonal and evaluation evidence

The supplied 40-source catalog and RESEARCH_FINDINGS.md describe selection bias, missing transcript licenses, synthetic forks and unverified reported outcomes. They do not establish a scientifically optimal invitation schedule. Consequently there is no message-count gate or conversion funnel, explicit refusal leads to abstention, and personal knowledge remains owner-supplied. Human review must assess naturalness and relational context; model graders alone are insufficient. No external raw chat dataset was copied into this application.

## Anthropic provider update

At the owner's request, retain OpenAI compatibility and add a native Anthropic Messages transport using the existing pinned HTTP client. Alternatives were an extra provider SDK, an OpenAI-compatible proxy, and replacing all model calls. Direct documented structured outputs preserve the existing bounded context, separate review, budgets and deterministic execution checks without adding dependencies or a proxy trust boundary. [Anthropic's schema constraints](https://platform.claude.com/docs/en/build-with-claude/structured-outputs) require moving unsupported bounds to descriptions while retaining original local validation. [Current model/version references](LLM_PROVIDERS.md#references-checked-on-2026-11-15) support the configured Sonnet 5.5 model and API version. Explicit selection prevents silent cross-provider disclosure. Mock contract tests validate headers/payloads, separate review, refusal/truncation, original schema enforcement, usage, semantic extraction and the existing OpenAI path. Live generation and bilingual naturalness remain unverified without an API key.

## Reconsideration triggers

Revisit SQLite when several coordinators or high throughput are required; add supported provider idempotency if offered; introduce semantic memory only after evidence-based bilingual quality testing; add browser interpretation only for a specifically authorized unstable DOM. Live release depends on real Telegram/model/email validation, participant consent and human evaluation rather than framework popularity.

## Security review update

OWASP session/CSRF/LLM guidance and Python SMTP documentation support server-side revocable sessions, strict public-host/body boundaries, least-authority model execution and verified TLS. Concrete source and race regressions led to a shared deterministic dispatch guard, atomic draft reservation, per-account Tinder automation and pre-generation consent gates. Strict CSP uses fixed external JavaScript assets. Resource budgets limit provider cost and unwanted automated volume. These controls were verified locally; managed deep-scan infrastructure, live-provider penetration tests and Docker runtime access were unavailable. See SECURITY_REVIEW.md for evidence and remaining risks.
