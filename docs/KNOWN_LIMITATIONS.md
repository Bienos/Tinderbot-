# Known limitations and remaining work

This delivery is a runnable, tested single-owner implementation with production-oriented safeguards. It is not a completed or independently validated production dating service.

1. **Live credentials absent.** Tinder, Telegram Business and SMTP calls are implemented and covered with mocks/contracts; no real Telegram message, model response or email delivery was tested. Enable them only with the required credentials, capabilities and consenting participants. Integration availability is not proof of end-to-end live operation.
2. **Conversational quality not established.** Without a model key, only a bounded fictional demonstration rule and abstention policies run. Live structured generation, independent review and semantic outcome extraction need provider smoke tests and bilingual human evaluation. A second model is not an infallible factuality or consent checker.
3. **Local outcome parsing remains bounded.** The temporal parser fixes reproduced cancellation/assent/contact false positives but cannot understand arbitrary language, sarcasm, implicit references, third-party meetings or complete date/time semantics. Optional semantic extraction broadens potential coverage but is unvalidated here. A weekday is not a timezone-resolved calendar date. No calendar booking is claimed.
4. **Telegram history and consistency limits.** Business updates discover newly observed conversations; the official API does not enumerate all prior chats or fetch arbitrary history. Delayed/out-of-order updates can race a send. There is no atomic external compare-and-send or server idempotency guarantee. Unknown delivery blocks that thread; no automatic resend or operator resolution interface is provided.
5. **Single owner/process.** The worker is a lifespan background task, not an independently scaled service. One ASGI worker and one active installation per SQLite database are required. A crash lease can delay restart by up to 120 seconds. Model calls use bounded timeouts but shutdown can abandon an in-progress generation safely. Production high availability/load testing is outstanding.
6. **Memory is deliberately modest.** Retained items are exact source-linked observations, with labels for questions, uncertainty, cancellation and boundaries, not a fully normalized semantic fact graph. No comprehensive supersession resolver or compression engine exists. The 24-observation cap can discard older details. The ablation measures source availability, not improved response quality.
7. **Privacy at rest depends on deployment.** SQLite/profile data is plaintext. Local modes/permissions and deletion are implemented; encrypted disks/volumes, backup expiry and external provider retention must be configured operationally. Deletion is logical, does not erase provider copies, and SQLite free pages/backups can retain bytes. Tombstones retain identifiers to prevent reimport.
8. **Consent is attested by the owner.** Grant flags do not independently verify the participant's consent, age or identity. There is no automated age/identity verification or consent-management service. Use only adult, explicitly consenting participants. Telegram unsupported media pauses processing.
9. **Notifications.** In-app/outbox behavior is tested. SMTP exactly-once delivery is not achievable here; ambiguous delivery is quarantined. iPhone push, calendar integration, natural-language scheduling/timezone resolution and notification preferences beyond email on/off are not implemented.
10. **Browser scope.** All browser tests use our fictional local site, not Tinder or an external authorized production DOM. The adapter is intentionally hardcoded to loopback port 8765; it opens ephemeral Chromium contexts rather than persisting third-party sessions. Expired third-party login, CAPTCHA, production DOM drift and external pagination are not claimed as tested.
11. **Tinder is implemented but live compatibility is unverified.** At the user’s updated request, an unofficial OpenDate-derived connector now supports discovery and automatic replies in consented threads. No credential was supplied, so no real account or message send was tested. Tokens expire; upstream endpoints can change; platform account restrictions remain possible. No login/token-renewal, swiping, stealth or bypass is included. See TINDER.md. Uncertain receiptless delivery blocks the thread and requires external investigation; exactly-once external execution cannot be guaranteed.
12. **Corpus limitations.** All 700 records are synthetic; 200 forks share prefixes with 200 originals. Contacts may be placeholders, location references may be implicit, labels are coarse and source redistribution rights are not established beyond the supplied package. No dating-success metric, statistical representativeness or naturalness score is inferred.
13. **Missing independent audit.** The named audit archive was not in either provided ZIP. Four visible parser failures were reproduced from the prompt and the requested failure categories have regression coverage. This is not a reproduction of an unseen report.
14. **Container validation blocked.** Docker CLI exists but daemon access is denied. Compose and image files are supplied; native startup and real Chromium testing are the executed deployment evidence. OS-specific deployment and container startup still need verification.
15. **Operational hardening remains.** No external penetration test, stress/load campaign, hosted multi-tenant authorization, distributed traces, dashboard push streaming, full error remediation UI or independent production review was performed. Structured metadata logs, durable activity/action IDs, counters and measured model usage hooks are implemented. Cost metrics require configured prices; zero is unpriced.

Tinder sends are automatic after connection and the one-time thread consent/disclosure grant. Receiptless uncertain sends have no automatic retry or resolution UI. A reserved action rejected/staled before dispatch is retained for audit; manual regeneration of an already attempted draft is blocked, so resolving such a turn may require external review or a newer incoming message. Tinder automatic execution is independently enabled per account and does not change Telegram mode. Global pause and simulation still block live sending.

Conservative traffic controls reduce request counts but have not been tested for Tinder account-ban probability or detection. There is no verified safe automation rate. Discovery can be delayed by idle polling (default up to 15 minutes), inactive-thread cache refreshes, budgets or server cooldowns. Verification/restriction signals and repeated rate limits pause the connection until the owner reviews it. Resume only after resolving the account condition through official platform controls.
